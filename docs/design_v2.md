# 생활·위험 소리 실시간 분류 — 설계서 v2

Nov 26, 2026 · @MJ

## 1. 목표

안드로이드 휴대폰 하나로 주변 소리를 듣고, 휴대폰 안에서 6종으로 분류해, 휴대폰 화면과 진동으로 알린다. 노트북과 인터넷 없이 집 안과 바깥에서 동작하는 것이 목표다. 기간은 최종 발표(12/17 목)까지 약 3주이고, 매주 목요일에 진행 발표와 진도보고서 제출이 있다.

**범위 안**

- 안드로이드 크롬에서 동작하는 웹앱 (홈 화면에 설치하는 PWA)
- 휴대폰 마이크 입력, 휴대폰 안에서 모델 실행
- 화면 알림, 진동, 알림 기록
- 집 안(초인종, 노크, 아기 울음)과 바깥(사이렌, 경적)

**범위 밖 (한계로 밝힘)**

- 화면이 꺼졌거나 다른 앱을 쓰는 중의 동작: 브라우저의 한계다. 네이티브 앱은 향후 과제로 둔다.
- 다른 집 초인종: 사용자 집 초인종 하나에 맞춘다.
- 소리의 방향과 거리 추정, 아이폰, 주머니 속 사용(측정만 한다)
- 추가 클래스(화재경보기 등): 12/10 발표까지 계획대로 끝났고 시험 데이터 30개를 구할 수 있을 때만 선택 과제로 한다.

**성공 기준**

| 항목 | 기준 | 측정 방법 |
| --- | --- | --- |
| 휴대폰 단독 동작 | 비행기 모드에서 소리 → 알림까지 동작 | 시연 |
| 분류 정확도 | 휴대폰 시험셋 macro-F1 (목표치는 기준 모델 측정 후 확정) | 시험셋 A, 시드 3개 평균 |
| 알림 성공 | 클래스마다 10번 중 알림이 뜬 횟수 (조용한 조건, 소음 조건) | 시험 C (앱 동작 시험) |
| 오경보 | 생활 소음 30분 동안 잘못된 알림 횟수 | 오경보 테스트 |
| 반응 속도 | 소리 시작부터 알림까지 3초 이내 | 화면 녹화 |
| 처리 속도 | 휴대폰에서 1회 예측 100 ms 이하 | 앱 안에서 측정 |

정확도 목표치를 먼저 정하지 않는 이유는, 휴대폰 마이크로 한 번도 재 보지 않은 상태에서 정한 숫자는 근거가 없기 때문이다. 기준 모델(v1)을 측정한 날 목표치를 정한다.

**개발 방식**: 1주차 코드와 데이터는 쓰지 않고 처음부터 새로 만든다. 공개 데이터도 원본에서 새로 추출한다.

## 2. 사용 장면과 분류 대상

분류 대상은 알림을 주는 소리 5종과, 알림을 주지 않는 '그 외' 1종이다. '그 외'가 없으면 말소리나 음악도 5종 중 하나로 분류돼 알림이 뜬다.

| 클래스 | 장면 | 포함 | '그 외'로 보낼 것 | 알림 |
| --- | --- | --- | --- | --- |
| 초인종 | 집 안 | 사용자 집 초인종 1종 | 다른 전자음(전자레인지, 세탁기, 휴대폰 벨) | 일반 |
| 노크 | 집 안 | 현관문을 손으로 두드리는 소리 | 문 닫히는 소리, 발소리, 타자 | 일반 |
| 아기 울음 | 집 안 | 영유아 울음 | 웃음, 옹알이, 어른 말소리 | 주의 |
| 사이렌 | 바깥, 창문 너머 | 구급차, 소방차, 경찰차 사이렌 | 음악 속 비슷한 소리 | 위험 (강조) |
| 경적 | 바깥 | 자동차, 오토바이 경적 | 도로 소음, 자전거 벨 | 위험 (강조) |
| 그 외 | 어디서나 | 위 5종이 아닌 모든 소리 | - | 없음 |

**휴대폰을 두는 위치**

- 집 안: 책상 위, 침대 위, 손에 든 상태. 원룸 기준이다.
- 바깥: 손에 들거나 화면이 보이는 곳에 둔 상태. 주머니 속은 소리가 먹먹해지고 화면이 잘못 눌릴 수 있어 범위 밖으로 두되, 시험셋 C에서 한 조건으로 측정해 한계로 보고한다.

## 3. 시스템 구조

모든 판단은 휴대폰 크롬 안에서 하고, PC는 학습할 때만 쓴다. 아래 세 가지는 서로 다른 문제에 대한 결정이고, 세 가지 모두 적용한다.

&#91;embedded content: 시스템 구조 · 휴대폰 실행과 PC 학습\]

위쪽이 사용자가 쓰는 흐름이고, 아래쪽은 개발할 때만 돈다. 녹음 모드로 모은 데이터가 학습을 거쳐 다시 휴대폰 모델로 돌아온다.

**① 앱 형태: 웹앱(PWA) + ONNX Runtime Web**

| 비교 | 웹앱(PWA) | 네이티브 안드로이드 앱 |
| --- | --- | --- |
| 기간(3주) 안 완성 가능성 | 높음. HTML과 JavaScript만 필요 | 낮음. 앱 개발을 새로 배워야 함 |
| 화면이 꺼진 상태 | 멈춤 (화면을 켜 두고 사용) | 동작 가능 |
| 진동 | 크롬에서 가능 | 가능 |
| 배포 | 링크 하나, 홈 화면에 설치 | 설치 파일 필요 |

웹앱으로 만들고, 화면이 꺼지면 멈추는 점은 한계로 밝힌다. 화면은 Wake Lock으로 켜 둔다.

**② 전처리 위치: 모델 안에 넣는다**

모델 파일(ONNX)의 입력은 16 kHz 모노 2초 파형(32,000개 값)이다. 음량 정규화, 멜 스펙트로그램(64×200), 3채널 복사까지 모델 안에서 계산한다. 멜 설정 초깃값은 창 25 ms(400개), 간격 10 ms(160개), 멜 64개, 0\~8 kHz다. 그러면 학습(PyTorch)과 휴대폰이 같은 계산을 하므로, 전처리 차이로 정확도가 떨어지는 문제가 구조적으로 생기지 않는다.

- 브라우저가 하는 일: 마이크 받기, 16 kHz로 변환, 최근 2초 보관, 0.5초마다 모델 실행, 알림 규칙. 16 kHz 변환은 모델 밖에서 일어나므로, 녹음 모드는 모델이 받는 16 kHz 신호를 그대로 저장한다
- 검증: 같은 wav를 PyTorch와 휴대폰에 넣어 6종 확률이 같은지 비교한다.

**③ 배포 방식: GitHub Pages + 오프라인 동작**

GitHub Pages에 올린다. https가 기본이라 마이크를 쓸 수 있고, 서비스 워커로 모델과 페이지를 저장해 두면 한 번 연 뒤에는 인터넷 없이 동작한다.

**마이크 설정**

`getUserMedia`의 `noiseSuppression`, `echoCancellation`, `autoGainControl`을 모두 끈다. 켜 두면 통화용 처리가 초인종이나 노크 같은 소리를 깎아 낼 수 있다.

**개발 환경**

- 휴대폰: 갤럭시 S24 Ultra(SM-S928N), 안드로이드 16, 크롬 158.0.8127.42 (바뀌면 `docs/recording_setup.md`에 기록)
- PC: RTX 3060 Laptop GPU 6 GB, RAM 32 GB

**알림 화면**

- 시작 버튼으로 듣기를 켠다(크롬은 한 번 눌러야 마이크와 진동을 허용한다). 큰 글자와 아이콘, 화면 전체 깜빡임. 위험 소리(사이렌, 경적)는 빨간색
- 클래스마다 다른 진동 패턴, 소리를 조금 듣는 사용자를 위해 켜고 끌 수 있는 알림음
- 최근 알림 목록(시각 포함), 듣는 중임을 보여 주는 음량 막대
- 진단 기록 (11/27 메모): 소리 빠짐 기록(1초마다 크롬 처리 시계·받은 소리 길이·track.stats)과 알림 목록을 같은 시계(performance.now)로 남기고 json으로 내려받게 한다. 오경보 측정 때 빠짐과 잘못된 알림이 겹치는지 보려는 것
- 알림 규칙 초깃값: 확률 0.7 이상, 2회 연속 같은 판단, 같은 소리는 5초 조용해진 뒤 다시 알림. 측정 후 조정한다. 알림음과 진동이 끝나고 0.5초가 지날 때까지 판단을 멈춘다. 휴대폰 마이크가 자기 알림 소리를 듣고 다시 알림을 띄우지 않게 하기 위해서다.
- **녹음 모드**: 데이터를 모을 때 쓴다. 알림과 같은 마이크 설정으로 녹음해 wav로 저장하고, 파일 이름에 회차 정보를 넣는다(4절). PC로는 USB나 클라우드로 옮긴다.

## 4. 데이터 설계

직접 녹음은 실제 입력과 같은 경로(앱의 녹음 모드)로 모으고, 공개 데이터는 양과 다양성을 보충하는 데 쓴다. 주 시험셋은 휴대폰 경로로 녹음한 데이터다.

**원칙**

1. **같은 경로로 녹음한다.** 휴대폰으로 녹음하되, 기본 녹음 앱(삼성 음성 녹음) 대신 휴대폰 크롬에서 연 웹앱의 녹음 모드를 쓴다. 기본 녹음 앱은 자체 소리 처리가 달라서, 실제 사용할 때 들어오는 소리와 달라진다.
2. **묶음 단위로 나눈다.** 같은 녹음 회차(날짜·장소), 같은 아기, 같은 원본 파일에서 나온 소리는 학습·검증·시험 중 한쪽에만 둔다. 코드로 자동 검사한다.
3. **배경도 같이 녹음한다.** 매 회차 앞뒤로 벨이나 노크가 없는 배경만 30초\~1분 녹음해 같은 분할의 '그 외'로 넣는다. 없으면 모델이 배경음을 단서로 외운다.
4. **새 출처는 확인하고 넣는다.** 샘플레이트와 스펙트로그램을 보고, 8 kHz 같은 저음질 출처는 쓰지 않는다(Donate-a-cry 제외).

**클래스별 출처와 목표 수량**

| 클래스 | 직접 녹음 (휴대폰 경로) | 공개 데이터 | 목표 학습 | 목표 검증 / 시험 |
| --- | --- | --- | --- | --- |
| 초인종 | 회차당 10번, 회차별 분할 | 없음 | 60\~80 | 20 / 30 |
| 노크 | 세기·날짜·문을 바꿔 5회차 이상 | ESC-50, FSD50K Knock (수량 확인 필요) | 150\~200 | 30 / 30 |
| 아기 울음 | 검증·시험 분할 원본을 스피커 재녹음 | CryCeleb2023 (학습, 16 kHz, 신생아 786명), AudioSet 평가용 60개 (시험), ESC-50 | 300 이상, 아기 100명 이상 | 30 / 50 |
| 사이렌 | 스피커 재녹음 (공개 데이터를 틀어 휴대폰으로 녹음). 실제 소리는 선택 | AI Hub 도시 소리, ESC-50 | 600 (상한) | 30 이상 / 30 이상 |
| 경적 | 스피커 재녹음. 실제 소리는 선택 | AI Hub 도시 소리, ESC-50 | 600 (상한) | 30 이상 / 30 이상 |
| 그 외 | 집 안 배경(조용함, 환풍기, 음악, 말소리, 가전 알림음), 바깥 배경(길거리, 버스, 걷기) | ESC-50 나머지, AI Hub 생활 소음 | 상한 2,400 | 배경 파일마다 10\~20개 |

CryCeleb2023은 허깅페이스에서 조건에 동의하고 받는다(CC BY-NC-ND 4.0, 비상업용). 병원 신생아 울음이라 배경이 거의 없어서, 배경 소음 섞기와 함께 쓰고 아기 ID 단위로 나눈다.

사이렌, 경적, 아기 울음은 직접 내기 어려워서 공개 데이터를 휴대폰 경로로 다시 녹음해 쓴다. 재녹음한 파일은 **원본이 속한 분할을 그대로 따른다.** 시험 분할의 원본은 시험에만 재생한다. 창문 너머로 들리는 소리는 집 안 배경과 섞고 높은 소리를 줄이는 증강으로 흉내 낸다.

**수량 기준의 근거와 멈추는 기준**

- 시험 30개 이상: 8개면 하나 틀릴 때마다 재현율이 12.5%p, 30개면 약 3%p 움직인다.
- 학습 데이터는 학습 곡선으로 판단한다. 25%, 50%, 100%로 학습해 50%→100%에서 점수가 거의 안 오르면 충분하다.
- 데이터 모으기는 3일로 제한하고, 못 채운 클래스는 한계로 기록한다.

**초인종 녹음 회차 진행**

1. 휴대폰을 정한 위치에 두고 녹음 모드를 켠다.
2. 벨 없는 배경을 30초 녹음한다.
3. 밖에서 벨을 10초 간격으로 10번 누른다.
4. 자동 탐지 결과가 10개인지 확인한다.

위치(현관 앞, 화장실, 침대, 책상)와 함께 배경(음악, 말소리, 환풍기, 물소리, 세탁기)과 휴대폰 상태(책상 위, 손, 이불 위)를 바꾼다. 하루에 몰아서 녹음해도 되지만, 학습·검증·시험은 회차로 나누고 시험 회차는 학습에 없던 위치·배경 조합으로 만든다. 학습 회차와 시험 회차는 시간을 떨어뜨리고(예: 오전 학습, 저녁 시험), 여유가 생기면 다른 날 시험 회차를 하나 더해 확인한다.

**녹음 조건 기록**

기기, 크롬 버전, 마이크 설정, 위치, 거리, 재생 볼륨을 `docs/recording_setup.md`에 적고, 모든 녹음과 테스트는 이 표를 따른다.

**파일 이름과 라벨링**

- 파일 이름: `클래스_날짜_회차_장소_기기.wav` (예: `doorbell_1129_s03_bath_phone.wav`). 회차 ID가 분할 단위다.
- 메타데이터 표 `data/meta.csv`: 파일, 클래스, 출처, 묶음(회차·아기·원본) ID, 분할, 라이선스. 분할 검사와 출처별 채점은 이 표를 기준으로 한다.
- 소리 구간 찾기: 직접 녹음은 음량이 갑자기 커지는 구간을 자동으로 찾고, 개수가 누른 횟수와 맞는지 확인한다. 구간 사이는 같은 회차의 '그 외'로 쓴다.
- 공개 데이터의 긴 녹음: 라벨에 시간 구간이 있으면 그 안에서 2초 창을 고르고, 창 안에 소리가 실제로 있는지 음량으로 확인한다.
- 라이선스: 데이터 파일은 저장소와 웹앱에 올리지 않고 모델 파일만 배포한다. 비상업용 데이터(CryCeleb 등)와 AI Hub 이용 조건을 받기 전에 확인한다.

## 5. 모델과 학습

모델은 ImageNet으로 사전학습된 MobileNetV3-Small(파라미터 약 152만 개)을 멜 스펙트로그램에 맞게 다시 학습한다. 작아서 휴대폰에서 빠르고, 데이터가 적어도 사전학습 덕분에 학습이 된다.

**학습 설정 (초깃값)**

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 입력 | 16 kHz 모노 2초 → 로그 멜 64×200 → 3채널 | 이미지 모델은 3채널을 받음 |
| 학습 방식 | 마지막 층을 6개로 바꾼 뒤 전체 학습 | 전이학습 |
| 학습률 | 앞부분 1e-4, 새 층 1e-3 (AdamW) | 사전학습한 부분을 덜 바꾸려고 |
| 배치 / 에폭 | 32 / 30 | 초깃값. 학습 곡선을 보고 조정 |
| 불균형 보정 | 클래스별 손실 가중치 1/√(학습 수) | 적은 클래스가 무시되지 않게 |
| 모델 선택 | 검증 macro-F1이 가장 높은 에폭 | 검증도 시험 A와 같은 구성(휴대폰 경로 녹음 + 검증 분할 재녹음) |
| 반복 | 시드 3개, 평균과 편차 보고 | 차이가 우연인지 구분 |

클래스 목록은 설정 파일에서 읽는다. 나중에 클래스를 더해도 코드를 고치지 않고 데이터와 설정만 바꾸면 된다.

**단계**

1. **기준 모델 v1**: 증강 없이 학습한다. 모든 개선은 이 모델과 같은 시험셋으로 비교한다.
2. **증강 실험**: 한 번에 하나씩 더하고, 나아진 것만 남긴다.
   - 배경 소음 섞기: 직접 녹음한 학습 분할의 배경만 사용, SNR 0\~20 dB
   - 음량 변화와 주파수 필터: 먼 거리, 주머니 속처럼 먹먹한 소리를 흉내
   - 스피커 재녹음: 아기 울음, 사이렌, 경적을 스피커로 틀어 휴대폰 경로로 다시 녹음
   - 끊김 넣기 (11/27 추가): 2초 창에 40\~50 ms 끊김(그 구간을 빼고 뒤를 당김)을 무작위로 넣는다. 휴대폰 크롬이 바쁠 때 마이크 소리를 조각으로 버리는 현상(2단계에서 발견, `docs/progress/report_w2_1203.md` 한계)을 흉내
3. **경량화**: ONNX로 변환해 휴대폰 속도를 재고, 100 ms를 넘으면 INT8로 양자화한 뒤 정확도가 얼마나 떨어지는지 확인한다.

## 6. 평가 설계

주 점수는 휴대폰 경로로 녹음한 시험셋 A의 6종 macro-F1이다. 실제 앱 동작은 시험 C로 따로 잰다. 출처마다 점수를 따로 보고, 한 출처만 유독 높으면 지름길을 의심한다.

**시험셋**

| 시험셋 | 내용 | 역할 |
| --- | --- | --- |
| A. 휴대폰 경로 녹음 | 초인종·노크·배경은 학습에 없던 위치·배경의 회차로 직접 녹음. 사이렌·경적·아기 울음은 시험 분할 원본을 스피커로 틀어 재녹음 | 주 점수 (6종 macro-F1) |
| B. 공개 데이터 원본 | 사이렌·경적(AI Hub, 장소·날짜 분리), 아기 울음(AudioSet 평가용 + ESC-50), 노크(ESC-50) | 참고 점수. A와 차이가 크면 휴대폰 경로의 영향 |
| C. 앱 동작 시험 | 앱을 켜 두고 클래스마다 10번 소리를 낸다. 초인종·노크는 직접, 나머지는 시험 분할 원본을 스피커로. 거리 1 m·3 m, 볼륨 고정, 휴대폰 위치(손, 탁자 위, 주머니 속), 조용한 조건과 소음 조건(TV나 음악을 정한 볼륨으로) | 알림 성공 횟수 |

**측정 항목**

- 분류(A, B): 클래스별 재현율(놓치지 않는 정도), 정밀도(잘못 알리지 않는 정도), F1, macro-F1. 시드 3개 평균
- 알림 성공(C): 클래스·조건별 10번 중 알림이 뜬 횟수
- 오경보: 알림 소리가 없는 생활 30분(집 안, 바깥 각각) 동안 잘못된 알림 횟수
  - (11/27 메모) 알림 앱도 녹음 페이지처럼 소리 빠짐 기록(`web/audio-input.js`의 `mic.diagnostics()`: 크롬 처리 시계, 받은 소리 길이, track.stats)을 남긴다. 알림이 뜰 때 시각과 함께 저장해, 잘못된 알림이 소리 빠짐 순간과 겹치는지 본다
- 반응 속도: 화면 녹화로 소리 시작부터 알림까지의 시간
- 처리 속도: 앱이 기록하는 1회 예측 시간(ms)

**지름길 확인 실험**

모델은 소리 대신 쉬운 단서(배경음, 음질, 녹음 기기)를 외울 수 있다. 모델을 바꿀 때마다 아래를 확인한다.

- 배경만 넣었을 때 알림 클래스로 판단하는 비율
- '그 외' 소리를 저음질로 바꿨을 때 판단이 바뀌는 비율
- 출처별(CryCeleb, AudioSet, ESC-50) 아기 울음 재현율 비교

## 8. 위험과 대안

가장 큰 위험은 휴대폰 안에서 모델을 돌리는 부분이라, 이걸 첫 2일 안에 확인한다. 막히면 휴대폰 마이크 → 노트북 판단 → 휴대폰 화면 구조로 시연한다.

| 위험 | 알아채는 법 | 대안 |
| --- | --- | --- |
| 멜 변환이 ONNX로 내보내지지 않거나 브라우저에서 안 돈다 | 1단계 변환 시험 | 합성곱(conv)으로 STFT를 직접 구현. 안 되면 멜을 JavaScript로 계산하고 PyTorch와 수치 비교 |
| 휴대폰에서 1회 예측이 100 ms를 넘는다 | 앱 속도 기록 | INT8 양자화, 실행 간격을 0.5초에서 1초로 |
| 크롬이 마이크 처리 끄기를 따르지 않는다 | 확인 녹음의 스펙트로그램 | 학습 데이터도 같은 경로로 모으므로 학습과 사용은 일치한다. 한계로 기록 |
| CryCeleb가 늦게 오거나 새 지름길이 생긴다 | 출처별 재현율 | ESC-50과 AudioSet만 사용, 배경 섞기 강화 |
| 바깥 사이렌·경적을 실제로 재기 어렵다 | 녹음 수 부족 | 길에서 기회 녹음 + 스피커 재생 시험, 한계로 기록 |
| 데이터 모으기가 길어진다 | 3일 제한 | 시험 30개를 먼저 채우고, 못 채운 학습량은 한계로 기록 |
| 화면이 꺼지면 멈춘다 | 사용 중 확인 | Wake Lock으로 화면 유지, 네이티브 앱은 향후 과제 |
| AudioSet 영상이 지워졌거나 받기 어렵다 | 받은 개수 | ESC-50 아기 울음과 CryCeleb의 다른 아기를 시험에 쓰고, 학습과 출처가 겹친다는 점을 한계로 기록 |
| 공개 데이터 이용 조건(비상업용, 배포 금지) | 다운로드 전 조건 확인 | 데이터 파일은 올리지 않고 모델만 배포. 조건이 안 맞는 출처는 빼기 |
| 녹음 파일 정리와 라벨링이 오래 걸린다 | 회차당 정리 시간 | 녹음 전에 파일 이름 규칙을 정하고, 자동 구간 탐지 + 개수 확인으로 줄임 |
