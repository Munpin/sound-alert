# 1단계-3: 휴대폰 안에서 모델 실행 확인 (11/27~28)

## 목적

설계서 8절의 가장 큰 위험, "휴대폰 크롬 안에서 모델이 돌아가는가"를 먼저 확인한다.
**이번 모델은 학습하지 않은 임시 모델이다.** 출력 확률은 의미가 없다. 확인하는 것은 세 가지뿐이다.

1. 전처리(멜 변환)가 들어간 모델이 ONNX로 내보내지는가
2. 휴대폰 크롬에서 PyTorch와 같은 결과가 나오는가
3. 휴대폰에서 1회 예측이 100 ms 안에 끝나는가

학습, 알림 화면, 오프라인 저장(서비스 워커)은 이번 범위가 아니다.

## 1. 모델 코드: `train/model.py`

입력은 16 kHz 모노 2초 파형 `[배치, 32000]`(값 범위 -1~1), 출력은 6종 확률 `[배치, 6]`이다. 전처리부터 확률까지 전부 이 모듈 안에 넣는다(설계서 3절 ②).

순서:
1. **음량 정규화**: 2초 창의 RMS를 목표값에 맞춘다. 단, RMS가 하한보다 작으면 하한으로 계산해서 **아주 조용한 소리는 키우지 않는다.** 조용한 방의 잡음이 커져 오경보가 나는 걸 막기 위해서다. 목표값과 하한은 설정 파일에 둔다(초깃값: 목표 -20 dBFS, 하한 -50 dBFS).
2. **STFT**: `torch.stft`를 쓰지 않고 **합성곱(conv1d)과 고정된 DFT 가중치**로 구현한다. ONNX의 기본 연산만 쓰게 해서 브라우저에서 확실히 돌게 하기 위해서다. 창 400(25 ms, Hann), 간격 160(10 ms).
3. **멜**: 멜 필터 64개(0~8 kHz) 행렬을 미리 만들어 버퍼로 넣고 행렬곱으로 계산한다.
4. **로그**: dB로 바꾼다(아주 작은 값은 잘라서 log(0)을 막는다). 고정된 평균·표준편차로 나눈다. 이 두 값은 나중에 학습 데이터로 정하고, 지금은 임시값을 쓴다.
5. **3채널 복사** → **MobileNetV3-Small**(torchvision, ImageNet 사전학습) → 마지막 층을 6개로 교체 → softmax

시간 프레임 수(200 또는 201 등)는 구현에서 나온 그대로 쓰고 기록한다. 클래스 목록은 설정 파일에서 읽는다.

## 2. ONNX 내보내기: `train/export_onnx.py`

- opset 17, 입력 이름 `waveform` `[1, 32000]`, 출력 이름 `probs` `[1, 6]`
- 저장 위치: `web/models/temp_model.onnx`
- 내보낸 뒤 Python의 onnxruntime으로 다시 열어 PyTorch와 출력 차이를 잰다(최대 절대 차이).
- 모델 파일 크기를 기록한다.

## 3. 비교용 고정 입력: `web/test/fixtures.json`

녹음 파일은 저장소에 올리지 않는다. 그래서 **코드로 만든 시험 신호**를 쓴다.
- 무음(전부 0), 1 kHz 사인파, 고정 시드 백색 잡음, 200 Hz→6 kHz 처프(높낮이가 변하는 소리)
- 각 신호의 32000개 값과 PyTorch 출력 확률을 JSON으로 저장한다.

## 4. 웹 페이지: `web/model-test.html`

녹음 페이지와 같은 사이트에 시험 페이지를 하나 더 만든다.

- onnxruntime-web을 쓴다. 버전을 고정하고 `docs/recording_setup.md`에 적는다. 나중에 오프라인으로 돌려야 하므로, 가능하면 CDN 대신 `web/vendor/`에 파일을 넣는 방식을 쓴다(어느 쪽이든 먼저 나에게 묻는다).
- 실행 백엔드는 WebAssembly(wasm) 기본. WebGPU가 되면 비교용으로 한 번 같이 잰다.

화면 기능:
1. **고정 입력 비교**: fixtures.json의 신호 4개를 넣어 PyTorch 출력과의 최대 차이를 보여 준다. 차이 0.001 이하면 통과.
2. **속도 측정**: 같은 입력으로 100번 실행해 평균과 상위 5%(p95) 시간을 보여 준다. 첫 실행 시간과 모델 불러오는 시간은 따로 보여 준다.
3. **마이크 실시간**: 녹음 페이지의 `audio-input.js`를 그대로 써서, 0.5초마다 최근 2초를 모델에 넣고 6종 확률 막대와 매번의 실행 시간을 보여 준다. 화면은 Wake Lock으로 켜 둔다.

## 5. 완료 기준 (1단계 완료 기준과 같음)

| 확인 | 기준 |
|---|---|
| ONNX 내보내기 | 오류 없이 내보내지고, Python onnxruntime과 PyTorch 출력 차이가 매우 작다 |
| 휴대폰 결과 일치 | 고정 입력 4개 모두 차이 0.001 이하 |
| 휴대폰 속도 | 1회 예측 평균 100 ms 이하 (S24 Ultra, 크롬 158) |
| 실시간 동작 | 마이크 실시간 화면에서 0.5초마다 확률이 바뀐다 |

**100 ms를 넘거나 결과가 다르게 나오면 고치기 전에 나에게 알린다.** 설계서 8절의 대안(INT8 양자화, 실행 간격 1초, JavaScript 멜 계산)은 내가 고른다.
