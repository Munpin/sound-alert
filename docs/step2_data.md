## 1. ESC-50

- `old_sound-alert/data/raw/esc50/ESC-50-master`를 `data/raw_public/esc50/`로 **복사**한다(옮기지 않는다).
- 클래스 대응: `door_wood_knock`→knock, `crying_baby`→baby_cry, `siren`→siren, `car_horn`→horn, 나머지 45종→other
- **묶음 ID는 원본 클립 번호**(파일 이름의 두 번째 칸)로 한다. 같은 원본에서 잘린 파일이 다른 fold에 있을 수 있으므로 fold만 믿지 않는다.
- 분할: fold 1~3 학습, 4 검증, 5 시험. 묶음이 여러 분할에 걸치면 한쪽으로 모으고 몇 건인지 기록한다.

## 2. AI Hub 도시 소리 (원본 압축에서 새로)

**2-1. 목록 먼저 (나에게 먼저 보고)**
- TS_1(교통소음), TS_2(생활소음)와 Validation의 **소분류 목록과 개수**, 라벨 json의 날짜·장소 칸 이름을 정리한다.
- 사업장소음(TS_3)은 쓰지 않는 것을 기본으로 하되, 소분류만 보여 준다.

**2-2. 뽑기**
- 차량경적, 차량사이렌: 전부
- '그 외' 후보: 생활소음 전 종류와, 교통소음 중 경적·사이렌이 아닌 소분류(바깥 배경으로 쓰려는 것). 어떤 소분류를 넣을지는 2-1 보고 뒤에 정한다.
- 압축 안의 검사값(CRC)으로 손상 여부를 확인한다.

**2-3. 묶음과 분할**
- AI Hub가 나눠 준 Training과 Validation을 **합친 뒤**, 라벨의 **녹음 날짜 + 장소**를 묶음 ID로 삼아 다시 나눈다(1주차에 Validation의 대부분이 Training과 장소·날짜가 같았기 때문).
- 묶음 단위로 학습 70 / 검증 15 / 시험 15. 클래스 비율이 분할마다 비슷하도록 나눈다.
- 학습 상한: 사이렌·경적 각 600개, '그 외' 전체 2,400개(설계서 4절). 상한을 넘으면 묶음을 돌아가며 고르게 뽑는다.

**2-4. 2초 창**
- 라벨의 소리 구간(area.start/end) 안에서 고른다. 창 안에 소리가 실제로 있는지 음량으로 확인한다.
- 16 kHz 변환은 품질 좋은 변환기(soxr 등)로 한다.

**2-5. 크롬 변환과의 차이 (나에게 먼저 보고)**
- 휴대폰 크롬은 7 kHz 부근부터 높은 소리를 줄인다. 공개 데이터를 Python으로 바꾸면 이 모양이 다르다.
- 확인 녹음과 Python 변환 결과의 주파수 모양을 비교해서, 공개 데이터에도 비슷한 필터를 씌울지 제안만 한다. 적용은 내가 정한다. "높은 소리가 살짝 줄어든 소리 = 휴대폰 녹음 = 초인종"이라는 지름길을 막기 위한 확인이다.

## 3. CryCeleb2023 (아기 울음 학습용)

- 허깅페이스 접근 승인은 받았다. `huggingface_hub`로 받는다(로그인 토큰은 내가 입력한다).
- 받은 뒤 정리: 파일 수, 길이 분포, 샘플레이트, 메타데이터(아기 ID, 녹음 ID, 순서)
- **2초 창 만드는 방법 (나에게 먼저 보고):** CryCeleb는 숨을 내쉬는 울음 구간만 잘라 둔 데이터라 조각이 짧을 수 있다. 실제 울음은 울음과 숨 들이쉬기가 번갈아 나온다. 길이 분포를 보고 방법을 제안한다(예: 같은 녹음의 연속 조각을 짧은 간격을 두고 이어 붙이기, 조각 하나를 2초 창에 넣기).
- 분할: **아기 ID 단위**로 학습 70 / 검증 15 / 시험 15. 시험의 주 데이터는 AudioSet이므로 CryCeleb 시험 몫은 참고용이다.

## 4. AudioSet 'Baby cry, infant cry' 평가용 (아기 울음 시험용)

- AudioSet 평가 목록에서 'Baby cry, infant cry' 클래스(ID `/t/dd00002`)의 영상 60개를 찾는다.
- yt-dlp로 해당 10초 구간의 소리만 받아 16 kHz 모노로 바꾼다. 받기에 성공한 개수와 실패 이유를 기록한다.
- 10초 안에 울음이 일부만 있을 수 있다. **파일마다 스펙트로그램을 한 장에 모아(목록 그림) 내가 보고 울음 구간을 고를 수 있게** 한다.
- 전부 시험 분할, 묶음 ID는 영상 ID
- 50개 이상 확보가 안 되면 설계서 8절 대안대로 ESC-50 울음과 CryCeleb 다른 아기를 시험에 더하고, 출처가 겹친다는 점을 기록한다.

## 5. FSD50K 노크 (선택, 확인만)

- 전체 데이터는 크다. **라벨 목록 파일만** 받아 'Knock' 클립 수를 세서 보고한다. 받을지는 내가 정한다.

## 6. 스피커 재녹음 도구 (사이렌·경적·아기 울음의 시험 A와 검증용)

설계서 4절: 직접 낼 수 없는 소리는 **검증·시험 분할의 원본**을 스피커로 틀어 휴대폰 녹음 페이지로 다시 녹음한다. 재녹음 파일은 원본의 분할을 그대로 따른다.

- `train/make_playlist.py`: 선택한 원본 2초 창들을 이어 하나의 재생용 wav를 만든다. 맨 앞에 시작 신호음(1 kHz 0.5초), 창 사이에 2초 무음. 각 창의 시작 시각을 csv로 함께 저장한다.
  - 시험: 사이렌 30, 경적 30, 아기 울음 50 / 검증: 각 20~30
- `train/align_rerecord.py`: 휴대폰으로 녹음한 파일에서 시작 신호음을 찾아 시각을 맞추고, csv대로 잘라 `data/raw/rerecord/`에 저장한다. 묶음 ID와 분할은 원본에서 물려받고, 출처는 `rerecord:<원본 파일>`로 적는다.
- 재생 볼륨, 스피커 종류, 거리(1 m)는 `docs/recording_setup.md`에 적는다.
